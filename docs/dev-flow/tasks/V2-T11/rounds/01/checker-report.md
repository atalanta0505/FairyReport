## 3. 合同逐项比对与代码审查细节

### 3.1 大纲生成系统提示词下钻强化 (`engine/app/writing/outline.py`)
- 在 `_build_outline_system_prompt` 中严格落实第 1 条规则：
  - “**深度要求（极重要）**：大纲必须全面细化下钻至三级（`###`）或四级（`####`）末级实施小节，每个二级节（`##`）下必须细分 2~5 个具体的末级小节，构建全书完整的标题骨架，严禁输出只有一级章或二级节的粗粒度空章。”
- 规范化约束第 3~5 条：带序号规范、禁止括号解释、标题标记仅用于结构性标题。
- 逻辑评估：能够有效引导大模型在 Step 2 生成完整且具备末级深度的标题树。

### 3.2 章节专属骨架提取与靶向填充提示词 (`engine/app/writing/writer.py`)
- **骨架提取函数 `_extract_chapter_skeleton(outline_md: str, chapter_seq: int) -> str`**：
  - 正则表达式覆盖中文数字章名（如 `# 第一章` ~ `# 三十章`）以及阿拉伯数字章名（如 `# 第1章`、`# 1.`）；
  - 进入当前章节后，收集所有以 `#` 开头的标题行（`#`、`##`、`###`、`####`、`#####`）；
  - 遇到下一个非二级节的一级章标题（`^#\s+` 且不以 `##` 开头）时精准 `break` 截断，天然过滤正文段落与列表项；
  - 边界处理完善：空大纲、章节序号非法（`<=0`）、不存在的章节均安全返回空字符串。
- **章节写作提示词重构 `ChapterWriter._build_chapter_write_args`**：
  - 自动解析 `ch_seq` 并提取 `skeleton`；
  - 当 `skeleton` 存在时，在用户 Prompt 中显式注入 `## 待填充的本章结构骨架（已锁定）\n{skeleton}\n\n`；
  - 升级 `## 写作要求（骨架靶向填充模式）`：
    1. **骨架锁定（最高优先级）**：严格保留上方【待填充的本章结构骨架】中的所有标题行及其完整文字与层级，严禁增删、修改或调换任何标题顺序；
    2. **末级小节精准填充**：在每一个最低级别标题（`###` / `####`）下方空一行，直接开始深入填充详实、专业、严谨的正文分析、工程参数、合规论证与数据表格；
    3. **非末级标题禁止堆砌正文**：一级章（`#`）和二级节（`##`）作为分类与结构导引，正文必须具体归属到对应的末级小节下方；
    4. **格式规范（极重要）**：标题独占一行空一行、表格每行末尾标准 `\n` 换行等。
- 逻辑评估：精准对齐产品负责人“全层级大纲 + 从最低级别标题开始填充内容”的范式升级意图。
